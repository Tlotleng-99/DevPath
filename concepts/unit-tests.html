Check every part before you serve

🥘 Tasting the Potjie

Before the guests arrive, taste the potjie piece by piece. Unit tests are little tasters that check your code automatically.

Try it yourself live

The chef wrote tests for the soup. One batch has a bug — one test fails. Find it, fix it, and the whole test tray goes green.

# remember: taste each part before serving

The proper cs name

A unit test checks one small unit of code automatically. It calls a function with known inputs and asserts the expected result.

  • assert — 'this MUST be true'.
  • One test = given inputs → expected output.
  • Run them all in one command. Every time.
def test_salt_is_right():
    soup = cook_soup()
    assert soup.salt == "just enough", "too salty lag!"

def test_gravy_is_thick():
    soup = cook_soup()
    assert soup.gravy_before_easter > 3     # 3 spoons minimum

Where they live: every serious project ships tests. They run in CI on every commit. If a change breaks something — the tests know before you do.

The story, slowly 🧠

1

Taste before serving

You wouldn't serve an untested potjie to 20 hungry guests. Unit tests taste-test each small part before strangers meet your code.

2

Assert the truth

'assert soup.salt == just enough.' A test is a promise the program must prove. If the promise breaks, the test goes red and screams.

3

Catch bugs early

A bug found by a test at 9am costs a coffee. The same bug found in production costs the weekend. Tests move bugs to where they're cheap.

4

Green is peace of mind

When all tests pass, you can sleep. When you change code later, you rerun the tray — and it tells you if you broke something.
